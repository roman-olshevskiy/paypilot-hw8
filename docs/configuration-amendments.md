# Уточнення конфігурації до першого inference

## 2026-10-29 · Windows TEMP

Перша спроба пілота зупинилася до judge HTTP і до chat, бо TEMP у Windows означає системний каталог. .env setdefault не замінив його числом. Застосовано окрему змінну HW8_JUDGE_TEMPERATURE=0.7; TEMP/TMP не змінювалися. Цільова температура з прогнозу залишилась0.7, модель Haiku4.5 та людські мітки не змінені. Початковий ERROR збережено, без спроб видати його за результат калібрування.

Forecast, rubric та label bytes не переписувалися після freeze. Подальші inference використовують нове ім’я параметра; ніякого мовчазного вилучення температури немає.

## 2026-10-29 · Контекст авторизованої сесії

Перші4 агентські відповіді повідомили, що клієнт не signed in; get_account повернув відповідну помилку. Це не доказ D27. Upstream ESC-001/002 мали context={} і розраховували на ID у тексті, тоді як shared /chat вимагає customer_id у тілі запиту. Власні working cases доповнено context.customer_id за їхнім уже заданим CUS-ID і clock2026-09-15; оригінали незмінні. Мітки/тексти/рубрика калібрування не змінювалися.

Початкові4 платні chats збережено й включено у витрати. Повторюється лише агентська частина4 chats; три валідні judge-відповіді не дублюються. Обидві серії — пілот, не фінальне калібрування чи частоти D27.
